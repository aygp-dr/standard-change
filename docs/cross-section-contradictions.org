** C-1 — the classification namespace is spelled both ways

Scan: =grep -c 'change:standard\|change:normal\|itil:standard\|itil:normal'=

| spelling | occurrences in spec-v1 |
|----------+------------------------|
| =change:normal= | 14 |
| =change:standard= | 6 |
| =itil:standard= | 1 |
| =itil:normal= | *0* |

§The label grammar states that =itil:*= is CLASSIFICATION and =change:*= is
LIFECYCLE — different namespaces about different subjects. The rest of the
document then uses =change:standard= / =change:normal= *for classification*,
including in two places that are not prose:

- =:711-712= the canonical label table, the document's own registry
- =:815-816= executable workflow YAML that calls =gh pr edit --add-label
  change:normal=

This is the same defect as =change:emergency=, which was corrected before the
seal — and only that one was corrected. Its two siblings were left, so the
spec now defines a namespace rule in one section and violates it in its own
label registry and its own shipped code.

A rebuild following the label table literally builds =change:normal= and
satisfies the labeller. A rebuild following §The label grammar builds
=itil:normal=. Both are faithful; they are not compatible.
