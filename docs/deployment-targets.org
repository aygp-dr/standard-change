* The test

From =spec.org= §C6:

#+begin_quote
A platform can attest to what is running only if it runs it.
#+end_quote

That single question sorts the candidates faster than any feature comparison,
because C6 — a platform-attested deployment record — is the capability the
whole model is short of, and the one that would let guard 5 stop guessing.

* The candidates

| target             | runs the code? | C6 | promote by identity | multi-replica | cost here |
|--------------------+----------------+----+---------------------+---------------+-----------|

** Bastille is the strongest local answer

Not a compromise. Three properties the current setup lacks:

1. *It runs the code, so it can attest.* =jls= and =bastille list= are the
   host's own statement about what is running — the same property that makes
   Cloudflare's =deployments list= attestation and GitHub's Deployments API
   bookkeeping. C6 is *met* here, locally, with no account.
2. *Real replicas with real identities.* Each jail has its own IP. Guard 5's
   convergence check would run against an actual fleet rather than the nginx
   round-robin stand-in of =experiments/004=, which faked a mixed fleet in one
   process space.
3. *A rollback target that survives.* A previous jail can be kept stopped
   rather than destroyed, which is a reachable rollback artifact — the thing
   =spec.org= says =non_fast_forward= is protecting and that GitHub Pages
   cannot offer at all.

What it does not give: cross-host scheduling, image digests, or anything
resembling a registry. Promotion would be "install this commit into that jail",
which is weaker than promoting a digest and must be recorded as such.

** Cloudflare Workers is the strongest remote answer

Complementary rather than competing — it exercises what jails cannot: a real
CDN, a gradual two-version split, and promotion by immutable version ID
(§C6). Worth having *both*, because they fail differently and the model claims
to be platform-neutral.

* Proposed shape [P — not built]

Two jails, clearly named and destroyable, on addresses outside the existing
=10.0.0.{10,11,20,21,30,31,32,41,42,50}= allocation:

#+begin_example
sc-staging-1   the singleton berth's estate
sc-prod-1      production
sc-prod-2      a second replica, so convergence means something
#+end_example

=targets/bastille/deploy.sh <env> <groups...>= would install the tangled apps
into the jail and restart them; =rollback.sh= re-points at the previously
installed commit. The deployment record is =jls= plus a file the *jail* writes
at start, not one the deploying job writes.

* Open question for the owner

The eleven existing jails are production. This note proposes creating three
more and does not do it — IP allocation and naming on =10.0.0.0/24= are the
owner's call, and a jail is not as free to create and destroy on a host that
is already doing real work.
