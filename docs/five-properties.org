* Statement

The promotion pipeline in =aygp-dr/standard-change= rests on five properties.
Each is a rule about one component; none is a rule about a host, a port, or a
vendor. Moving the pipeline to microservices, Kubernetes, or Cloudflare Workers
changes the primitive that provides each property. It does not change the
property.

1. The berth is a lease.
2. The calendar is a serialized store with a non-overlap check.
3. The runner writes its own verdict.
4. The scheduler consumes its trigger before acting.
5. The coordinator re-reads at every step and has a tail that runs on every
   exit.

* The properties
:PROPERTIES:
:CUSTOM_ID: properties
:END:

** P1 — The berth is a lease

The right to take the path to production is a mutex with a holder identity and
an expiry. Exactly one change holds it; the holder is named; an unrenewed lease
lapses. It locks the path, not a host: replicating staging does not change the
invariant.

Failure it prevents: two changes deploying to staging in the same window, each
reading the other's build as its own.

** P2 — The calendar is a serialized store with a non-overlap check

Reservations are written by compare-and-swap, and the store rejects a window
that overlaps an unresolved window on the same environment. =current= compares
=end= to now. Closure codes are a closed set (=passed=, =failed=,
=cancelled=, =expired=, =held=) and only =reap= writes =expired=.

Failure it prevents: two agents booking the same slot and both succeeding; a
lapsed window answering "yes, you have a window."

** P3 — The runner writes its own verdict

The component that executes a suite records the observation, and the record
names the instrument, the actor, the build, and the environment. A caller may
request a run; it may not supply the result. UAT is the one instrument that is
a person, and its record says so.

Failure it prevents: a label added by hand asserting a measurement nobody took;
a deployer reporting its own success.

** P4 — The scheduler consumes its trigger before acting

A request to promote is removed from the queue before any action is taken on
it. A failed action does not re-fire; re-requesting is a human act. The
scheduler books windows and nothing else; it never names a slot.

Failure it prevents: a change deployed twice because the trigger survived a
crashed activation.

** P5 — The coordinator re-reads at every step and has a tail that runs on every exit

No guard trusts a fact checked earlier in the same run. Guard 4b is the
explicit form: re-read the authorization stack at the moment of reliance,
confirm the head has not moved. A final block releases the berth and closes
the window on success, refusal, failure, and crash alike.

Failure it prevents: authorising on stale evidence; a berth held forever by a
dead run.

* What the substrate decides and what it does not

The substrate decides: the CAS primitive, the lease primitive, the loop runtime
(poller, controller, cron), the build identifier's form, and what an
environment physically is.

The substrate does not decide: which component writes which field, that
verdicts name their build and instrument, that reservations cannot overlap,
that triggers are consumed once, that guards re-read, and that cleanup runs on
every exit. Those are the pipeline. A port of the pipeline that keeps the names
and drops any one of the five has ported the vocabulary and not the design.
