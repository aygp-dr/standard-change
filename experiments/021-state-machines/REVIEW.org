* What this is

Five engineers are each building a state machine of this pipeline with the
*pull request as the core primitive*. This document is the bar they are graded
against, written before their models exist, plus a review of the three artefacts
that already model it — =spec.org=, the code, and =tla/= — including where those
three disagree with each other today.

*The central warning, and it is not rhetorical.* =spec.org:2802= defines the
domain entity and then rules out the encoding by name:

#+begin_example
| *change* | a proposed alteration, with a record | a commit, a branch, or a PR |
#+end_example

Both TLA modules index every single variable by =PRs= (=tla/StandardChange.tla:16=,
=tla/Labels.tla:29=), and every scenario in =scenarios.org= is written about a
numbered PR. So the primitive the brief proposes is the one the governing
document explicitly says the change *is not* — and the two existing formal
models already took it, which is a large part of why they lose what §5 shows they
lose. A model whose state vector is a function of one PR has nowhere to put
trunk, the estate, the calendar, the served build, or the forge's own opinion,
and every one of D4, D6, D9, D11, D13, D17 and D18 is a change endangered or
refused by exactly those.

* 1. The eighteen scenarios

The question asked of each: *what property does it demonstrate, and can a state
machine hold that property?*

- *T* — a transition. An edge between two named states.
- *G* — a guard predicate. A condition on an edge.
- *N* — neither. The property is about *what we could and could not tell*, about
  the *range of an oracle*, about the *relation between a record and the world*,
  or about the *implementation that reads a verdict*. Some are reachable by
  adding subjects or widening a codomain; none is reachable by adding states. A
  naive machine loses them *silently*, which is the failure mode this repository
  exists to document.

** Part A — the labeller

| id | property demonstrated | T / G / N |
|----+-----------------------+-----------|
| L1–L3 | the manifest is a function of the diff, and fans out | *T* — a derivation, not a state |
| L4 | a change can be classified and deploy nothing | *T*, and it is the case guard 6 gets wrong |
| L5 | classification precedence: normal outranks standard | *G* on the classifier |
| L6 | the empty manifest is a legitimate value | *T*, and see INV-11 — empty must be *provably* empty |
| L7 | ownership is by path, not by file type | *T* |
| L8 | control-plane paths classify as normal | *G* |
| L9 | the labeller *removes*; a shrinking diff shrinks the manifest | *T* — the half most models omit |
| L10 | a human write to a derived artefact must not survive | *G*, an authority predicate, not a state |
| L11 | reclassification is ordinary, in both directions | *T* |
| L12 | a verdict is bound to a SHA and dies when the SHA moves | *G* — INV-5/6 |
| L13 | *the negative fixture.* The catalogue rejects its own run if the labeller cannot fail | *N* |

L13 is the first *N* and sets the pattern. It is not a property of the pipeline;
it is a property of *the checker of the pipeline*. No arrangement of states
expresses "this suite produced no verdict because it cannot produce a negative
one". It requires a *proof obligation on the model* — §4 item 6 — and §5.9 shows
two live instances where the existing models failed it.

** The six a state machine will lose, and exactly how

Each fails differently. A model can answer one and lose the other five.

*** D2 — the composition of the deployed thing is not a state of the change

=scenarios.org:100= asserts that on staging, the *untouched* groups serve the
production SHA. That is not about the PR; it is about the *contents of an
environment*, and it needs an =ENVIRONMENT= entity carrying a per-group build
map. A PR-primitive model holds =holder = p= and calls staging occupied — which
is exactly what =tla/StandardChange.tla:34= and =tla/Labels.tla:55= do — so it
cannot say *what staging is serving*. The mixed-app trap is then unstateable, and
D6 and guard 5 go with it. Confirmed: neither TLA module has any environment
entity [E].

*** D4 — the trigger is an event on trunk

The content of =scenarios.org:131= is that the PR did not move and =main= did
(=scenarios.org:155=). If trunk is a field on the PR, the model can express the
*consequence* but not the *cause*, and will put the invalidation edge at the PR's
next action rather than at trunk's push. =spec.org:1112= is explicit: guard 0 at
claim is a convenience, guard 4b at reliance is load-bearing. =StandardChange.tla=
does have a =mainV= counter and a =MainMoved= action (=:235=), which is the right
shape — and it then implements the *pre-correction* behaviour, stealing the berth
(§5.6).

*** D11 — unmeasurable is a state, and it is not "ungated"

=scenarios.org:362=: guard 2 needs evidence about a build, and the instrument
that produces it is not in that build. A two-state gating model has
={gated, ungated}= and files this under =ungated=, which reads as *the gates have
not passed* — indistinguishable from red. It is neither: it is *unmeasurable*, a
third value at the level of the whole suite. =tla/StandardChange.tla:43= types
=gated= as =BOOLEAN= and has no =GatesFail= action at all, so the model cannot
even express red, let alone unmeasurable [E].

*** D13 — the record ran ahead of the world

=scenarios.org:429=. =settle.sh= had =gh pr merge ... && ok=; the merge refused,
execution continued, the PIR was posted, the summary claimed success. A model
with one =merged= bit *cannot represent this state* — and that is the trap,
because unrepresentability here reads as proof of safety. It needs *two*
variables (INV-24). All four existing models have one: =pipeline_sim.Change=
has no merge field distinct from =State.COMPLETED=; =Labels.tla:62= has
=merged[p]= as a single =BOOLEAN= [E].

*** D16 — the guard was correct, the caller dropped the verdict

=scenarios.org:559=: =./change/guard4.sh "$PR" | tail -1=. The guard refused;
the pipeline's status was =tail='s; production was cut over. There is no state
this pipeline "is in". It is a property of the *implementation of the transition
function* — whether a computed verdict reaches the code that branches on it. A
state machine assumes verdicts are consumed by construction, and that assumption
is precisely what failed here, twice, eight hours apart, in the script written to
replace the one that failed first. Answerable only by a *realisability
obligation* (INV-29). §5.3 shows it is still live.

*** D17 — the model is more capable than the world

=scenarios.org:607=. Guard 0's refusal sits inside =if [ "$state" = "BEHIND" ]=
(=change/queue.sh:25=), and =BEHIND= has never been returned: 0 of 14 open PRs
after 163 commits landed on main. A model whose =mergeStateStatus= ranges over
={CLEAN, BEHIND, DIRTY, UNSTABLE}= will exercise guard 0's refusal on every run
and thereby *certify a guard that has refused nothing in this repository's life*.
The model is not wrong about the predicate; it is wrong about the *oracle's
range*, and nothing inside the model can see that. The answer is not a state, a
guard, or an invariant, but a *measurement obligation attached to the model*
(INV-28). =spec.org:2679= already states the audit question; no artefact in the
repo implements it.

*** D18 — forfeit on entry is ordinary, and unknowable in advance

=scenarios.org:669=. Every guard passed; the acceptance suite refused at the
estate; the window was spent. *T* for the forfeit edge, and the models will get
that. The *N* half is the finding: the refusal was knowable at review time and
*no scheduler can know it*, because the thing that refuses runs only against a
deployed estate. A model that has only the edge has modelled the outcome and lost
the reason there is no guard for it. It also exposes a gap in the closure enum —
see §3.3.

** The two that are about time, not state

D7 (=scenarios.org:188=) and D12 (=scenarios.org:413=) are *liveness*. D7: a
failed change must not hold the berth forever, and =scenarios.org:197= records
the question as *undecided*. D12: every individual booking was correct and the
trajectory was absurd — twenty-five windows on one day. Neither is refuted by any
reachable-state check.

=tla/= is the only artefact with the vocabulary, and it does not use it [E]:
=tla/StandardChange.cfg= and =tla/Labels.cfg= declare only =SPECIFICATION Spec=
and =INVARIANT= / =INVARIANTS= lines. No =PROPERTY=, no temporal formula, no
fairness. Every check in the repository is safety-only. A model that offers only
safety invariants must *say so* and must name D7 and D12 as the properties it
does not check.

* 2. The invariants

Stated so they can be checked mechanically. Each names its source. A model is
judged on whether it can *state* each one, whether it can *check* it, and whether
removing the corresponding guard makes the check fail.

** A. The berth

*INV-1 — BERTH SINGLETON.* =|{c : holds_berth(c)}| ≤ 1= at every state.
(=spec.org:176=.) Check: a reachable-state predicate. Every model has it; alone
it discriminates nothing — and see INV-27, because =tla/StandardChange.tla:263=
states it *vacuously*.

*INV-2 — A BERTH IS A LEASE.* Every held berth carries an *owner* and a
*deadline*. A berth with no expiry is not a lease, and INV-1 becomes a deadlock
rather than a queue. (=spec.org:142=; capability C3 at =spec.org:255=;
implemented at =change/state.sh:64=, =:102=.) *No existing model has the
deadline* — not =pipeline_sim= (a counting model, =sim/pipeline_sim.py:122=), not
=label_sim=, not either TLA module [E]. Check: the berth is a record, not a
boolean, a PR id, or a count.

*INV-3 — EVERY EXIT RELEASES OR RETAINS, NEVER STRANDS.* For every path that ends
a change's occupancy of the path to production, either the berth is released, or
the change remains on the path with a live deadline. *No path may close a window
while leaving the berth held.* (=change/reap.sh:46=; violated in the
implementation — §3.3 and §5.4.) Check: enumerate terminal transitions; assert
=held ⇒ (∃ open window ∨ ∃ live deadline)=.

*INV-4 — PREEMPTION EXTENDS; STALENESS RELEASES.* A change whose verdict was
invalidated by *someone else's* merge keeps its position, gets a deadline
extension, and is marked =revalidate=. A change that went stale on its own
releases. "The berth is never taken away by someone else's merge"
(=spec.org:1156=; the two edges at =:1164–:1169=; implemented at
=change/state.sh:102=, =:113=). *All three formal models get this backwards* —
§5.6. Check: two distinct edges out of "invalidated", selected by *who caused
it*.

** B. Verdicts in time

*INV-5 — A VERDICT NAMES ITS BUILD.* Every observation, approval and deployment
record carries the content hash it was measured against. No bare boolean verdict
anywhere. (=spec.org:2629=; =docs/interfaces.org:41=; =docs/interfaces.org:289=
makes =(change_id, instrument, sha)= the query key, explicitly *not*
=(change_id, instrument)=.) Only =sim/pipeline_sim.py= satisfies this today
(=:93–:95=, =:106–:107=) [E].

*INV-6 — A VERDICT IS COMPARED AT RELIANCE.* Every guard that consumes a verdict
compares =verdict.sha= to the head *at the moment it relies on it*, not at the
moment the verdict was written. (=spec.org:2635=.) Check: no guard reads a
verdict without reading the head in the same evaluation. *Resetting a verdict on
push is not this.* =tla/StandardChange.tla:76–85= and =tla/Labels.tla:444–451=
model the reset and have no hash at all; the binding is documentation
(=tla/Labels.tla:59=, =:61= say "THIS head" about bare booleans) [E].

*INV-7 — SUPERSEDED IS NOT CURRENT.* For a =(subject, instrument)= pair, only the
latest observation counts; earlier ones are history and must not be aggregated
with it. (=spec.org:2603=; D15; the fix shape is
=group_by(.name) | map(max_by(.started_at))=.) Check: every aggregation over
observations is preceded by a per-name max. No existing model can even reach the
defect: all four hold one scalar verdict per axis, so the *stale* case is caught
and the *superseded-but-counted* case is unrepresentable [E].

*INV-8 — OBSERVATIONS ARE APPEND-ONLY.* A withdrawal is a *new row*, never an
update, because an audit must see that a verdict was taken and then retracted.
(=docs/interfaces.org:294=.)

*INV-9 — RE-CHECK AT RELIANCE.* For every guard =g= whose subject can change
after =g= is evaluated, there is *no path* on which =g= is evaluated at =t1= and
relied on at =t2 > t1= without re-evaluation at =t2=. (=spec.org:182=,
=:1230=; =docs/interfaces.org:57=, =:428=.) Check: annotate each guard with its
subject's mutability; for every mutable-subject guard, exhibit the re-check edge.
This is the invariant the repository is organised around, and the one a
PR-primitive model is least equipped to state, because "the subject changed" is
an event on something that is not the PR.

** C. The third value

*INV-10 — EVERY READ IS THREE-VALUED.* Every question the model asks an external
system has codomain ={yes, no, cannot-determine}=. =cannot-determine= refuses
*differently* from =no=, and it *blocks*. (=spec.org:2590=, =:2699=, and =:2740=
— "every verdict enum in this spec is three-valued"; =docs/interfaces.org:26=;
=docs/exit-codes.org:15= assigns exit 4, =:26= says 4 blocks.) Check: *no guard's
return type is a boolean.* Mechanical, and the cheapest discriminator here. Of
four existing models, exactly one arm of one model satisfies it
(=sim/pipeline_sim.py:63–80=, the =Deploys= enum) [E].

*INV-11 — EXEMPTION REQUIRES POSITIVE EVIDENCE.* A guard may exempt a change only
when an oracle *proved* the exempting condition and the record *names that
oracle*. Absence of evidence that the condition fails is =indeterminate=, and
indeterminate is not exempt. (=spec.org:212=: "=deploys(c)= is three-valued,
never a set that may be empty".) Check: every =exempt= branch is reachable only
from a successful oracle read; a failed read reaches =abstain=.

*INV-12 — A VOID VERDICT IS NOT A FAILING ONE.* A suite whose self-test did not
run, or ran and failed, produces *no verdict* — its PASS is void, which is
neither pass nor fail. (=spec.org:1817=, =:2664=.) Check: three constructors;
=void= does not unify with =fail=.

*INV-13 — CONVERGENCE, NOT LIVENESS.* Guard 5 is satisfied only when *N* samples
all report the expected build. More than one distinct build is =UNCONVERGED=; an
unreachable probe is =indeterminate=. (=spec.org:2150=.) Check:
=health(env, sha) ∈ {converged, unconverged, unreachable}=; no boolean =healthy=
anywhere — =docs/interfaces.org:328= forbids it by name, and
=tla/Labels.tla:84–87= has three of them [E].

** D. Namespaces and closure

*INV-14 — THREE SUBJECTS, THREE NAMESPACES.* Classification (what kind of change),
lifecycle (how far it has got) and estate (the state of the world) are separate.
Exactly one classification; at most one active lifecycle state; the estate's
flags on *something that cannot be deployed*. (=spec.org:2810=; =README.org:186=;
implemented in the declaration at =change/label-owners.tsv:86–87=.) Check: three
disjoint enums; no value of one appears in another's domain.

*INV-15 — AN ESTATE FLAG IS NOT A FIELD ON A CHANGE.* A freeze or estate emergency
is a property of the world, blocking everyone *including its declarer*. A flag
attached to a change is a flag whose carrier is exempt from it. (=spec.org:2812=;
=docs/interfaces.org:312=.) The repository's *best* piece of modelling is here,
and it is worth quoting as the target: =change/label-owners.tsv:54= declares an
unprefixed =emergency= label as "ESTATE STATE ... grants NO exemption to whatever
PR carries it. Separate from =itil:emergency= because an emergency handled
outside the pipeline has no PR to classify, and hanging the CLASS on a PR to
represent it would hand that PR a bypass of every blocker." *That sentence is the
whole of INV-15, and no model in the repo implements it* — =tla/Labels.tla:65–66=
has =freeze= and =estateEmg= as global variables, which is right, but =spec.org=
itself never separates the two emergencies (§5.1).

*INV-16 — A CLASSIFICATION IS EXACTLY ONE, AND IT EXPIRES AT RELIANCE.* Zero or two
classifications is an *error state*, not a default arm; and a class set at =t1=
must be re-confirmed at activation, not trusted. (=spec.org:2789=;
=change/label-owners.tsv:86=; D9 at =scenarios.org:257= — #44 carried
=itil:emergency= for two hours after the exercise that set it and would have been
exempted from guards 0 and 1 on that basis; the eligibility rule at
=scenarios.org:330=.) =tla/Labels.tla= gets this right and is the model to copy:
=Label(p)= re-derives standard/normal on every push and never touches emergency
(=:135–:140=), so a declared emergency that receives a push holds *two* classes —
reachable *by design* — and =ClassGuard= refuses the claim rather than the state
(=:485=) [E].

*INV-17 — EXPIRED IS NOT FAILED.* Closure codes are a closed enum
={passed, failed, cancelled, expired, backed-out}=. =expired= asserts *nothing was
attempted*; =cancelled= asserts somebody decided; =failed= asserts an attempt that
did not succeed. A change closed =expired= keeps its classification, its approval
and its observations, and is left *eligible and unbooked*. (=spec.org:2786=,
=:2817=; =docs/interfaces.org:266=; correctly implemented at =change/reap.sh:16=,
=:66=, and =change/schedule.sh:285=.) *No formal model has closure codes at all*:
=sim/pipeline_sim.py:41–43= declares =FAILED=, =REJECTED=, =CANCELLED= and never
assigns any of them; =tla/Labels.tla:60= collapses =change:failed= and
=change:backed-out= into one boolean, and =:220= says of expiry "Nothing was
attempted, so no closure code" — which is the exact collapse =spec.org:2787=
forbids [E].

** E. Manifest, record, and authority

*INV-18 — THE MANIFEST IS DERIVED, NEVER ASSERTED.* =manifest(c) = f(diff(c))=,
owned by automation; a human write does not survive the next derivation. Any
exception is a *declared, visible deviation* carried into the record.
(=spec.org:150=; L10; the declared exception =labeler:skip= at =spec.org:729= and
=change/label-owners.tsv:29=.)

*INV-19 — ADDING AND REMOVING ARE DIFFERENT AUTHORITIES.* Two verbs per fact. A
person asks; automation may *answer* the ask but may not *invent* one.
(=docs/interfaces.org:63=; =README.org:214=; the reaper deliberately refuses to
re-assert the human's ask, =change/reap.sh:66=.) The repository has a
machine-readable form of this — =change/label-owners.tsv=, with =human_add= and
=human_rm= as separate columns — and §5.2 shows its own enforcer is blind to one
of its two tombstone values.

*INV-20 — AN ACTION LABEL IS NOT A REQUEST.* =deploy:*= asserts *work is in
flight*. A hand-written one is a forged assertion, and the workflow it triggers
must *re-establish the fact* rather than believe it. (=spec.org:2354=, =:2367=.)

*INV-21 — THE ORACLE IS INDEPENDENT OF THE CALLER.* An instrument records its own
result; where a verdict genuinely comes from the caller, the record says so by
name. (=spec.org:2617=; =docs/interfaces.org:49=.)

*INV-22 — AN ESTATE WRITE RECORDS WHO AND WHY, IN THE SAME WRITE.* If the identity
cannot be established, the control refuses. An unattributable freeze is not a
safer freeze. (=spec.org:637=.)

** F. The estate and the world

*INV-23 — THE DEPLOYED COMPOSITION IS MODELLED.* An environment carries a per-group
build map; on staging the changed groups serve =H(c)= and the untouched groups
serve the production build. (=scenarios.org:100=.) Check: environment state is a
map, not an occupancy flag.

*INV-24 — THE RECORD IS NEVER AHEAD OF THE WORLD.* "We recorded merged" and "the
forge attests merged" are *separate variables*; the record may not assert a fact
the world has not confirmed. Likewise for deployed. (D13; =spec.org:156= — the
Deployments API is a self-report with good provenance about *who claimed it*, not
evidence about what is running.)

*INV-25 — LIVE, CLOSED, MERGED ARE THREE EVENTS IN THAT ORDER.* Not
interchangeable; the berth is released on =merged=, a repository event, while it
protects the estate. (=spec.org:2138=.)

*INV-26 — PRODUCTION FIRST.* =deploys(c) = ∅ ∨ served_build(production) = T= at
merge, with =deploys(c)= three-valued per INV-11. (=spec.org:181=.)

** G. Obligations on the model itself

Not invariants over states. Conditions the model must satisfy to be worth
checking at all — and where every *N* scenario lives.

*INV-27 — EVERY GUARD, AND EVERY INVARIANT, MUST BE SHOWN TO REFUSE.* For each, a
test that fails when it is removed — in *all* arms, not only the happy one.
(=spec.org:221=: =000='s self-test had exactly the right two cases and the guard
exempted its way past both.) Check: mutation. *Two live violations are in this
repository's own models*: =sim/pipeline_sim.py:305= asserts =not self.regressed=
— the D4 invariant, the simulator's headline claim — and =self.regressed= is
assigned exactly once, to =False=, at =:129=, and never set true anywhere in
=sim/=; and =tla/StandardChange.tla:263='s =AtMostOneHolder= is literally
=TypeOK:51= restated, so it is implied and cannot fail. Both are inside checked
suites. Both are class 7 committed by the code written to enforce class 7 [E].

*INV-28 — EVERY GUARD MUST NAME ITS ORACLE AND THAT ORACLE'S OBSERVED RANGE.* What
does it read, what value does it test for, and *has that value ever been observed
from that oracle in this configuration?* A guard with zero lifetime refusals is a
hypothesis, not a control. (=spec.org:2679=; D17.)

*INV-29 — A VERDICT MUST BE UNPIPEABLE.* Any step whose verdict gates a later step
must be structurally incapable of having its status discarded by formatting.
Capture, test, then format. (=spec.org:2651=; D16.) In shell this is a lint: no
=guard | anything=. §5.3 shows three live violations.

*INV-30 — A NEGATIVE TEST MUST NAME WHAT IT REFUTED.* A negative run that reports
only "something failed" cannot distinguish the property it was written for from
any other. =tla/StandardChange.cfg:8= checks the single conjunction =Safety=, so
=tla/check.sh:21= (asserting =Guard4b=FALSE= violates =NoRegression=) and
=tla/check.sh:29= (asserting =ProdFirst=FALSE= violates =NoMergeBeforeProduction=)
grep the *identical string*, =Error: Invariant Safety is violated=. Neither can
tell which conjunct broke; either could be passing on =TypeOK=. =tla/Labels.cfg:16–27=
lists its eleven invariants individually and =tla/check.sh:75= greps the specific
name — the fix exists in the repository and was not applied to the other module
[E].

* 3. The states this system can reach that have no name

=spec.org:2776= makes the right demand: *a rebuild is graded on whether it can
name each one, not on whether it prevents them.* A model that cannot represent an
unnamed state is wrong in the direction that looks tidy — the defect has no home,
so the model proves its absence.

* 4. The grading rubric

100 points. Weighted toward what a PR-primitive model is structurally likely to
get wrong, because that is what will discriminate between five models that will
all get INV-1 right.

Scored against the model *as designed*, not as it happens to behave. Per
=experiments/019-rebuild-001/HELD-OUT.org=: "does the rebuild's design make it
*unrepresentable*, or did it merely not happen to be written that way? Only the
first counts."

The bar is not hypothetical. Every item below is satisfied by at least one
existing artefact in this repository, and no existing artefact satisfies more
than a third of them.

** 1. Subjects other than the change — 25

says the change *is not* the PR.

| the calendar is a subject with windows that lapse on their own, independent of any change, and with a *deadline* (D14, D18, INV-2, INV-17) | 5 |

** Disqualifiers

Independent of score. Each converts a silent failure into a certified one.

1. *A boolean guard.* If any guard's codomain is ={true, false}=, the model
   cannot express the class that fired at least six times here (=spec.org:2595=),
   and every result it produces about refusals is suspect.
2. *One =merged= bit.* Collapsing the record and the world makes D13
   unrepresentable, and unrepresentability reads as proof.
3. *=expired= modelled as a kind of =failed=*, or closure as a boolean. Loses the
   only signal that says the slots are too short (=docs/interfaces.org:266=).
4. *A classification that is also a lifecycle state.* One label asserting both
   "an emergency is in flight" and "this change is exempt" is the defect that
   took longest to find here (=spec.org:2820=) — and §5.1 shows =spec.org= still
   commits it.
5. *A verdict with no build.* (=spec.org:2629=.)
6. *An invariant that cannot fail.* If a single invariant in the submission is
   implied by the type invariant, the whole suite is suspect until each one is
   mutation-tested.

** Tie-breakers, in order

1. The model that *names more of §3*. Naming is the graded skill
   (=spec.org:2778=).
2. The model whose guards and invariants are shown to refuse — by mutation, not
   by argument.
3. The model that is *smaller*, given equal coverage. =spec.org:87= is the
   reminder: the machinery exists because a contract is missing, and a model that
   makes the machinery look inevitable has reproduced the architecture's mistake
   at one remove.
4. The model that says what it cannot do.

** The anti-pattern to watch for

A model that is *more capable than the world*. It will look like the best
submission: every guard has a refusing arm, every arm is exercised, the state
graph is complete and connected. D17 is what that looks like from outside — a
guard that has never refused anything, whose model exercises its refusal on every
run. Ask of every refusing edge: *what real oracle emits the value on this edge,
and has it ever?* A complete state graph over an oracle range nobody measured is
a fiction with a coverage report.

happens — the side ADR 0003 rejects [E]. This is acknowledged as open elsewhere
(=README.org:385=, =research/findings/label-state-machine.org:93=), but the configuration as

*This is the single most useful thing in §5 for the five builders*: INV-4 is a
place where reading the models will actively mislead them, and only reading

** 5.7 The two TLA modules disagree about what break-glass costs

=tla/StandardChange.tla:160=, =:180=, =:220= all require
=(emergency[p] /\ approved[p])=, and =NoSilentBypass= (=:274–:275=) states the
rule with the approval conjunct.

=tla/Labels.tla:332–336= — =Promote= — grants the break-glass arm on
=IsEmergency(p)= alone. *There is no =approved= variable in =Labels.tla= at all*
[E]. Its comment at =:329–:330= claims it is "the break-glass path of
StandardChange.tla"; it is strictly weaker. =sim/label_sim.py:149= has the same
weakening.

Worse: =Labels.tla:333–:335= requires only =berth[p]= for the emergency arm, so an
emergency can reach =prodAct= with =verdict = "fail"=. =StandardChange.tla:271='s
=NoRedGatesShipped= exists precisely to forbid that and is documented at =:270= as
having "NO emergency bypass". =Labels.tla= has no analogue: *a failing gate never
blocks anything in that model*. =spec.org:913= is unambiguous — "Guard 2 and guard
5 have no bypass at all" — and D3's headline assertion (=scenarios.org:127=) is
exactly this case.
